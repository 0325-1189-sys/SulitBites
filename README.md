# Sulit Bites - Food Ordering Management System (Java web application)

OOP final project, Scenario 4. The whole system is written in **Java**. The server uses only the JDK
(`com.sun.net.httpserver`), so there is nothing to install except Java 17 or newer. The pages are plain
HTML and CSS generated by the Java code. There is no JavaScript.

## Run it on your computer
1. Install JDK 17 or newer and the Extension Pack for Java in VS Code.
2. Open this folder in VS Code, open `src/com/sulitbites/Main.java` and click **Run**.
3. Open http://localhost:3000

Terminal: `javac -encoding UTF-8 -d out $(find src -name "*.java")` then `java -cp out com.sulitbites.Main`
Windows PowerShell: `javac -encoding UTF-8 -d out (Get-ChildItem -Recurse src -Filter *.java).FullName` then `java -cp out com.sulitbites.Main`

## Settings (environment variables, all optional)
| Name | Meaning | Default |
|---|---|---|
| `PORT` | port of the website | 3000 |
| `DATA_DIR` | folder of the local data file `db.json` | `data` |
| `FIREBASE_URL` | Firebase Realtime Database URL. When set, data is shared online and survives restarts on any host | not set (local file only) |

## Hosting: Netlify link + Java server on Render + Firebase database
Netlify cannot run Java, so the Java server runs on Render and Netlify forwards every request to it.
The address stays `https://sulitbites.netlify.app`. The folder `netlify-site` holds the only file Netlify needs (`_redirects`, no JavaScript).

How everything is connected:
```
GitHub repo (0325-1189-sys/SulitBites)  ->  Render builds and runs the Java server  ->  Firebase Realtime Database
Netlify (sulitbites.netlify.app)  ->  forwards every request to the Java server on Render
```

1. **GitHub**: put this whole folder in your repository and push.
2. **Render** (render.com, free): New > Blueprint (or Web Service), pick the repository. It builds with the `Dockerfile` and `render.yaml`.
   The environment variable `FIREBASE_URL` connects the database. After the deploy, the Render log must say `Loaded data from Firebase`.
3. **Netlify**: open `netlify-site/_redirects`, make sure the address in it is your Render address, then drag the `netlify-site` folder into the Deploys page of your Netlify project.
4. **Keep it awake** (optional but recommended): free Render services sleep after 15 minutes. A free monitor at uptimerobot.com that opens your Render address every 5 minutes prevents slow first loads.

## What it does
- Customers: register and log in, browse the menu (they see whether each food is available), cart, checkout with Cash, GCash or Card, receipts, order history
- Cashier: dashboard, orders (change status), payments, walk-in orders, receipts that can be printed
- Admin: everything the cashier can do, plus products (add, edit, delete), **stock** (add, set, mark out of stock) and customers. Only the admin can change stock
- Receipt: store name, branch, date and time, cashier, customer, items, discount, total, payment. Only Admin and Cashier can print it (Ctrl+P)
- New accounts are **pending** until the admin approves them (Account requests page). Pending accounts cannot log in
- A cancelled order counts as 0.00, returns its stock and cannot be changed again

## Four Pillars of OOP
- **Abstraction**: abstract classes `User`, `FoodProduct`, `Payment`; interfaces `Stockable`, `Repository`
- **Inheritance**: `Admin`, `Cashier`, `Customer` extend `User`; `Meal`, `Drink`, `Dessert` extend `FoodProduct`; `CashPayment`, `GCashPayment`, `CardPayment` extend `Payment`; `FileRepository` and `FirebaseRepository` implement `Repository`
- **Polymorphism**: `discountRate()`, `getRole()`, `process()`, and `Repository.save()` behave differently in each subclass
- **Encapsulation**: private fields with validated setters, hashed passwords, `final` template method `calculateTotal()`, immutable `OrderLine`
